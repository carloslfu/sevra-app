# Synthetic Excel application references

All business data is invented. `scripts/make_excel_behavior_fixtures.py` uses the repository's FODS writer and LibreOffice 25.8.7.3 (`30742500f2d3eb4366ac312fa33d3dcabdb3eba5`) to calculate and save 88 reference workbooks (84 conversion examples and four held-out originals) across ten scenarios: starting states, changed inputs, zero-interest/period loans, signed half-cent payments and commissions, partial numeric text, combined blank/invalid inputs, renamed lookups, blank and invalid inputs, negative rounding, and exact text/whitespace boundaries. The original 43 files retain their original bytes; later cases extend the corpus. `hashes.json` records their exact SHA-256 hashes. This is independent spreadsheet-engine evidence, not Microsoft Excel execution qualification.

Cases cover inventory/reorder with a shipment action, invoices, timesheets, cash flow, commission, PMT loans, production/IFERROR, VLOOKUP quotes, Gregorian date boundaries and Unicode/leading-zero text codes. `cases.json` contains independently written JavaScript translations for deterministic integration checks. Those translations are **never provided to actual local-model trials**; the model receives original files and workflow instructions. Expected results come from saved spreadsheet values, not those JavaScript translations. Four `holdoutFiles` cases (blank Loan periods, blank principal with invalid interest, blank date offsets, and invalid Inventory reorder input) are never imported into the local model's workbook or supplied as comparison examples. Only the independent post-publication saved-edit/reopen/Undo checks use them.

`business-vba.bin` is a small synthetic CFB/MS-OVBA container generated by the script. Inventory XLSM files contain its readable ShipStock source. It exists to test reading and translation; the original VBA is never executed. Action reference results use explicitly changed inputs and LibreOffice recalculation, so these files do not claim real VBA execution equivalence.

`vbaProject.bin` is the genuine XlsxWriter example downloaded from:

- https://github.com/jmcnamara/XlsxWriter/blob/main/examples/vbaProject.bin
- SHA-256: `0ced1464b3677e98f5e3a8c5d80135e18dc98dca39299f1a8cfd2a00999fbf9f`
- Size: 15,872 bytes. Used only for parser coverage of real VBA streams.
- BSD 2-Clause license retained in `XlsxWriter-LICENSE.txt`, from https://github.com/jmcnamara/XlsxWriter/blob/main/LICENSE.txt.

Run the generator only when changing the fixtures; it needs a local LibreOffice install. Ordinary tests use the committed originals and do not launch Office or require LibreOffice. Passing finite examples does not prove universal spreadsheet behavior.
