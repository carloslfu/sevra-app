Method: the probe starts the pinned Splash 1.6.1 helper directly with the app's launch arguments plus `--persistent-cache on`, a new `--cache-dir` and a quota. It makes the ordinary chat header (2,572 tokens, from the app's own prompt code) at the 64K context under a 1 GiB quota and copies the four data files aside. It restores them into a new directory under an 8 GiB quota at 64K, sends the first chat prompt, extends it by 7,000 tokens eight times (61,264 tokens, one output token each), then sends the header with a different 3,000-token suffix. It restores the same files again at the 32K context and sends the first chat prompt.
Result: the header made under the small quota is taken back under the larger one (1 state, 80 KV blocks, 0 left behind) and resumed to its last complete page, 2,560 tokens. The cache name is the same at 32K, where the 64K header is taken back and resumed too, so one header serves both memory tiers. The full conversation wrote 867.7 MB while it ran and left 1.76 GB of slot files at the stop; the new conversation after it still resumed the header.
