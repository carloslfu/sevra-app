# Owner direction: a customizable native workbook application engine

Recorded from the owner's Sevra side conversation on October 28, 2026.
These quotations establish requested product direction and authorization to
update the design. They do not establish implemented capabilities.

## Owner's request

> Does the user have the ability to modify the home or at least modify a few things from the home? Adding actions or whatever makes sense. We want to make this app fully customizable, like their own app, their own thing they can modify, like a desktop app engine. Do you get what I'm saying?

> Think about what we would need to do to make this possible and think in depth. Do deep research on the codebase and on what we would need for home: everything we would need, including automations. We want this to be a full-blown engine that's way more powerful than Excel

> Tell me what you understand so I know you understand it well before doing it

## Interpretation presented before authorization

The assistant described a user-owned workbook application: persistent Home and
spaces; reusable named actions with typed inputs; multi-step workflows;
scheduled, file and data-triggered automations; shared workbook data, assets,
search, calculations and provenance; an extensible native component engine;
inspection, versioning, undo and export; and local AI that constructs and
operates saved behavior without having to invent it again on each invocation.
The assistant proposed inspecting actual code, researching relevant designs,
identifying gaps and defining implementation and acceptance requirements.
The strength relative to Excel would need evidence from real jobs.

## Authorization

> do it, tell the agent or make it so the design document contains all of this

Scope: research and maintain the repository-owned design and implementation
requirements. No engine implementation or operating-system automation was
performed by this documentation update.
