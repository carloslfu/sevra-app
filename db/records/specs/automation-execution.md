# Foreground automated workflow execution

This extends [[records/specs/automation-planning]] toward E4 in [[records/specs/native-app-engine]]. Native timer/configuration/device registration, event/condition triggers and E5 remain required. A bounded foreground core/CLI path is an implementation step, not a substitute for useful native scheduling.

## Authority

Planning permission cannot execute. A distinct nonserializable AutomationExecutionSession needs a new explicit Source, foreground-drafts-v1 policy, exact automation/workflow/typed inputs and local-AI allowance. AI defaults false; interpretation requires true before authorization. It never authorizes external effects or acceptance of business proposals. Capabilities bind this Workbook instance, generation and Source. Open/copy/reconstruction issue none. Pause/revoke fences claims, prepared model/native work and publication. The coordinator checks authority before model loading and again at request/publication. No transaction spans inference or review; existing model exclusivity stays intact.

Same-version reauthorization may explicitly resume its active run under a new generation while retaining original dispatch evidence. Changing version while a run is queued/running/waiting-review/needs-attention requires finishing or explicitly stopping it first. Native UX must expose that choice, not silently retarget/drop work. Completed/cancelled releases overlap.

Explicit manual continuation of a scheduled run records a new manual-operation Source and live capability, without relabeling the original invocation or enabling future schedules. Stop requires no execution grant and creates none. Independent manual continuation has its own authority and still obeys run/claim cancellation fences.

## Dispatch

Dispatch checks exact live execution grant, completed bounded catch-up, one active run and a pending authorized version/generation. Future slots defer after clock rollback; slots over24 elapsed hours late are skipped with evidence. Product observation defaults to Date(); tests/advanced tooling may supply an explicit normalized instant. Dispatch Source, workflow invocation/steps/outbox, occurrence-to-run binding, occurrence state and active-run pointer commit atomically through the same captured ledger. Original workflow policy is automation-drafts-v1. Stable occurrence uniqueness prevents duplicate runs across tokens/notifications/restarts. Trigger identity never becomes a domain fulfillment/effect identity.

The existing bounded coordinator executes and stops at review, attention, cancellation or completion. All business mutations remain drafts until separately accepted. An active blocked run prevents another run for that automation. Future pending calendar draft requests may coalesce. Terminal runs permit a successor without deleting history. Same-token retries recover receipts only under valid current authority; receipts cannot revive revoked work. Inert reconstruction preserves every binding and Source without sessions or execution.

## Explicit foreground CLI

`automation-run-once WORKBOOK EXACT_DEFINITION_ID EXPECTED_GENERATION START_AFTER OBSERVED_AT TOKEN [--allow-ai [MODEL_DIRECTORY]]` creates a new exact current-process execution grant and performs one bounded preparation/dispatch/continuation. Expected generation is0 for first authorization. Instants require an explicit zone; observed time must not precede start. Tokens are1...240 UTF-8 bytes, reserving suffix space for child operation receipts. AI permission is explicit; model path requires that flag. A deliberately supplied old observation is simulation/advanced tooling, not evidence of real-time dispatch.

A page with catchUpRemaining=true does not dispatch. Inspect progress before another explicit operation using the refreshed generation and a new token. Reauthorization preserves coverage but supersedes pending preparation and earlier capabilities. Repeating an original operation uses its original arguments/token; current receipts recover without duplication, superseded grants refuse. No routine timer poll should use run-once because every new operation is a new grant. The future native timer will retain one verified local grant and call the shared bounded planner/dispatcher instead. Exit ends this process's permission. Output states timerInstalled=false and permission=this-process-only. Business review is separate.

Manual continuation of an existing scheduled run creates a separate Source; CLI attribution remains programmatic. Native Continue/Stop use their direct human gestures. `workflow-inspect` exposes original scheduled invocation and latest claim authorization metadata. Business read intentionally refuses those technical Sources.
