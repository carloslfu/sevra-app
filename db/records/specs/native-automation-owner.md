# Native automation owner

Status: reviewed implementation contract. This slice implements native schedule configuration, persistent device-local grants and a conservative foreground driver over schema21. Full E4/E5/release acceptance remains open. See [[records/specs/native-app-engine]], [[records/specs/automation-execution]] and [[records/operations/implementation]].

## User experience

Activity has a Schedules destination beside saved runs. Search saved automations, inspect exact workflow/typed inputs, upcoming local/UTC occurrences, device status and any active run. Create or edit with a workflow picker, native typed parameter fields, daily/weekly/monthly/yearly recurrence, explicit named time zone and clock fields. Preview is inert. Saving keeps intent; Enable on this Mac is a distinct, clear action whose scope covers the exact immutable version, its arguments, local-AI allowance and draft-only workflow. Never infer authority from a Source, chat transcript, copied package or a saved armed row. Version edits require a fresh explicit enable and cannot change a currently active run. Pause revokes this device registration and its exact current workbook generation. Run once creates a separately attributed manual workflow and does not consume a scheduled occurrence or enable future runs. Input/evidence identity and all business approvals remain existing core contracts.

Routine polls and reopening the same physical workbook restore the exact authorized generation from the local registry without generating new authorizations. Pause, superseding CLI authorization or an edited definition never silently enlarges the old grant. An old registered version remains pinned and is labeled when a newer saved version exists. Failed saves keep inputs; registry failures never report a running timer.

## Device boundary

Store at most 32 grants in a private, bounded, atomic JSON registry under this app's Application Support directory, outside every workbook. Register only explicit selections; never scan disks. Bind workbook UUID, package and database device/inode/birth identities, app-owned bookmark, exact definition/activation/generation/authorization Source and allowAI. Encode filesystem identifiers as strings without Double loss. Resolve bookmarks without UI or mounting. Missing, copied, replaced, symlinked, revoked or inaccessible files defer/refuse. A rename on the same filesystem may retain permission only when both physical identities still match. Bookmark staleness alone never grants access to a different object. A second physical workbook with the same UUID cannot acquire a concurrent grant. Imported archives and reconstructed packages have new identities and stay inactive.

Registry mutations use a dedicated cross-process lock, exact-entry comparison, private permissions, bounded decode and atomic durable replacement. Corrupt data is preserved and refuses operation, not reset. No database migration or second business ledger. Distributed atomicity is not claimed: Enable first commits exact workbook permission, then saves local registration; a failure before durable registry publication starts no driver work and explains the retained permission decision. An error after rename may leave an unknown durable outcome, so reload actual registration and report that the requested state could not be confirmed. Pause first removes the device grant so old workers cannot publish, then attempts exact workbook pause. Failure is reported honestly; manual work is untouched. Removing a stale device entry must not pause a newer grant created independently.

A package-only core recovery entry point validates exact saved scope and returns a process capability with a live device fence. Every automation authorization check invokes that fence, including worker claim, model acquisition and publication. The fence verifies registry entry and physical identity and checks cancellation. Core/model/CLI ordinary tools cannot hydrate permission from workbook data. Registry checks must not hold its lock while entering workbook locks.

## Driver and lifecycle

One app-wide owner, at most one automatic operation at once and round-robin bounded registration traversal. Work and I/O run off the main actor. Timer polling does not create Sources while no slot is due; cache next due and periodically revalidate. Plan catch-up in bounded pages, never dispatch an intermediate stale page, then bind at most one exact run. Resume queued work and reviewed continuations under the same live grant. Needs-attention waits for explicit inspection/retry. Waiting review does not spin new claims. Clock rollback never executes a future slot; overlap, 24-hour lateness and coalescing reuse the core. No repeated authorization per tick.

This qualification slice conservatively runs automatic work only while Sevra is active. Loss of application focus, screen/system sleep, user-session resignation, termination, warning/critical memory pressure, Low Power Mode or serious thermal state cancels the active operation and defers new work. Wake alone does not prove active permission. App launch defaults ineligible until a real application-activation event. No undocumented screen-lock API and no claim that session-switch notifications fully detect locking. Background execution with closed windows remains an explicit open gate; the final E22 contract is unchanged. No app-quit timer/helper, notification permission or hidden hosted fallback is installed. Interactive local model work has priority at admission; active automatic work cancellation/yield and full battery/fairness policies must be qualified before background adoption.

## Three review passes

1. Usability: separate Save intent, Preview, Enable on this Mac, Pause and manual Run once. Never repeat confirmation on every poll. Native controls expose scope and exact retained inputs, with conversation/voice authoring still an open qualification rather than a JSON editor.
2. Authority and failure: UUID alone cannot distinguish copies. Bind both physical objects plus exact authorization Source; live fences block removal/replacement during a model request. A pre-publication registry failure means no driver activation; an error after atomic publication requires reloading the actual state. Local removal precedes workbook pause; stale removal cannot revoke another owner's new grant. No silent automatic acceptance or authority from imported history.
3. Recovery and load: persistent atomic registration, bounded decode/traversal, source-idempotent core, inert archives/reconstruction, busy/review backoff, canceled late callbacks and conservative focus gate. Do not confuse simulated headless lifecycle tests with actual macOS privacy/background qualification.

The conservative active-app gate is our engineering choice.

## Scoped implementation and qualification, October 29

Schema21 is unchanged. Activity now links Schedules, searchable saved definitions, native typed workflow inputs, calendar preview, inert create/edit, exact-version Enable on this Mac, pause/removal, separately attributed manual Run once and saved-run inspection. Editing returns to the new immutable version. Device badges require the current definition, generation, authorization Source, AI policy, armed state and both physical identities to match. Manual Run once rechecks original workbook and interaction ownership before continuation. Voice/conversation authoring and actual visible interaction remain unqualified.

SevraAutomationUI owns a private bounded registry and the shared native controller. The registry binds at most 32 explicit grants to workbook UUID, package/database device/inode/birth identifiers encoded losslessly, passive bookmark and exact saved authority. It uses private modes, no-follow reads, bounded JSON, a dedicated cross-process lock, exact-entry compare-and-remove and durable atomic replacement. Corrupt bytes stay preserved. Copies, reconstructed packages, same-path package/database replacement, symlink aliases and superseded generations cannot borrow permission. A rename works only when bookmark resolution returns the original physical objects; refusing a replacement is preferable to searching disks. No registry data enters the workbook, schema or business ledger.

Restoration creates a new process capability without a new authorization Source or generation. Its live fence checks private entry, physical identity and cancellation at authority use and publication. Claim, heartbeat, failure/retry/cancel, interpretation request/response and workflow completion check this fence inside their commit guard. Removing a grant during the actual prepared checkpoint rolls publication back. Pause removes this Mac's exact entry before quiescing and attempting workbook pause; stale removal cannot erase or pause a newer independent grant. A failure after registry rename may have an unknown durable outcome: native copy says it cannot confirm the requested state and reloads actual state. A pre-publication registry failure starts no controller work and retains the separately saved authorization decision. Cross-file atomicity is not claimed.

One app-wide owner starts with the app, serializes automatic operations, traverses grants fairly in bounded rounds and runs file/core work off the main actor. Ineligible or idle polling and unchanged review waits create no Sources. Due work uses the existing bounded planner/dispatcher and ProductAI coordinator; prepared pending occurrences recover without duplicate runs or repeat authorization. Future occurrences after clock rollback defer. Interactive work cancels automatic work and awaits its release before model acquisition. Admission requires the active app and a key window, no interactive busy owner, normal memory pressure, acceptable thermal state and Low Power Mode off. Documented focus, screen/system sleep, user-session, memory and thermal notifications defer/cancel, with launch ineligible until activation. No complete lock-detection claim, app-quit helper or background/closed-window support follows from this implementation. Termination quiesces the owner before save flushing.
