# Single Excel import review

Scope: [[records/plans/single-excel-import]] and [[records/specs/single-excel-import]], under [[sources/notes/2026/11/single-excel-import]]. This is a bounded source-preview implementation/security/UX review, not independent certification. The same implementation agent performed an adversarial pass; no separate reviewer agent or external audit is implied.

## Repaired findings

1. App publication initially nested captured transactions. Reused the existing native publication body inside a single conversion transaction, so app version and ready state commit together. Deterministic publication/rebuild and portable integrity checks pass.
2. Native app Undo restored a whole old row, including protected Excel outputs. It now restores only the edited inputs, letting the shared formula engine recalculate. Eight business cases and installed Inventory edit/Undo demonstrate the correction.
3. Letting the model copy dataset IDs, schemas and app versions produced repeated invalid builds. The host now supplies those values from its immutable capability; the model chooses short aliases with write flags only. Wrong/missing/foreign bindings, stale versions, copied-workbook reuse, generic record forgery and hidden worksheet tables refuse.
4. Early local grammar rejected minProperties/maxProperties. The simplified binding schema uses supported grammar constructs; private planning/build grammar construction is covered directly.
5. The independent reviewer initially misunderstood SDK and fixture semantics. It now receives a concise Excel-specific contract: native Table handles refresh, row events have exact IDs and logical keys, filtered assertions count matching rows, synthetic fixtures have no spreadsheet formula plans, and labels/header names are permissible constants. A real-model negative review rejected a mounted table with missing editing behavior despite an embedded instruction to approve it.
6. Installed generated editors could keep stale selected row IDs after saving, and draft values survived Undo. The conversion guidance now clears controlled selection/drafts after successful saves, preserves failures and blocks edits while busy. Independent real-model probes now require two edits of the same row and a data-row/header selection counterexample. Early one-edit successes do not qualify this stronger behavior.
7. A host origin banner used a conditional empty SwiftUI Group; its asynchronous load did not appear. Its loading task now attaches to a persistent container. Installed reinspection confirms the origin and import-details link appear, including after reopen.
8. Internal schema instructions appeared as a user chat message. Requests now display the approved workflow in plain language, with matching request provenance. The first focused rerun caught a mismatch between visible message and captured request; both now use the same friendly text and the existing authority check remains intact.
9. Malformed saved conversion metadata could force-unwrap or collide on worksheet indexes. Conversion reads now validate state, dataset uniqueness, bounded inspection, ordered indexes and plan shape; mapping enumerates validated sheet positions and checks count. Missing/duplicate indexes refuse without creating data.
10. A changed clarification with unchanged plan text could leave an old app presented as current. Publication saves the exact clarification and the UI compares both. Portable-copy tests cover this counterexample.
11. Workflow chevrons looked actionable, and counts used plural forms for one row/formula. The interface uses bullets, correct counts and omits zero cached-formula text. Installed normal and constrained-window inspection passes.

12. Keyboard focus could enter an offscreen native input without revealing it. Native text fields/buttons now scroll their bounds into view when becoming first responder. The original headless failure was retained; all 17 native groups now pass, and installed Tab navigation reveals the input at 922 × 682 points without changing its value. Refocusing an already visible input keeps the scroll position. macOS Tab behavior still follows the user's unchanged keyboard settings; VoiceOver and all-control keyboard navigation are not qualified.
13. Successful table-only import retained an obsolete cancellation error. First successful import now clears that failure, with a deterministic cancellation/import counterexample and installed verification. Empty workbooks no longer offer a purpose form, build/update choices or duplicate original-file links. Normal supported formulas no longer produce a prominent compatibility warning solely because they began with saved Excel values.
14. The original-file menu still exposed a separate Excel updater shortcut. Excel now has only Use saved file, which returns to the conversion workspace; reviewed updates remain a secondary action inside that workspace. CSV/TSV shortcuts remain intact. The installed menu and update-target/mapping route were inspected. Incoming row counts now use the correct singular form.

## Threat and integrity pass

Planning has no write tools and building has a private host capability enforced again in core dispatch/publication. Imported values, formulas, metadata and source comments do not grant authority. Exact source bytes are verified before/after isolated parsing. Existing archive bounds, XML protections, extraction worker sandbox and hash verification are retained. Macro/ActiveX/embedded/external contents are reported and never executed. Generic code cannot forge host-owned conversions, device grants or successful check proofs. Model-supplied tests are evidence, not authority; a separate model review and explicit device access approval remain required.

Reads during a build are restricted to imported datasets and the conversion's existing app. No unrelated conversation history is included in that phase. Source identity, table schemas and app/version identity cannot be supplied or expanded by tool arguments. All worksheet aliases must remain accessible. Business records are not mutated by authoring checks, which use synthetic isolated workbooks. Runtime writes use existing exact-version/capability checks and immutable history. Cancellation/stale transitions retain committed data and refuse late publication. Original files, table-only fallback and reviewed existing-table updates remain available.

## Qualification boundaries

Synthetic small-business files do not establish success on every customer workbook. Formula support remains the existing declared subset. VBA, external refresh, original Excel formatting/protection and automatic extension of formulas into new rows are not implemented. Planning samples are bounded, and native builds currently allow at most twelve nonempty worksheets and bounded context. Actual model generation can fail or misunderstand business rules. Review access and test important workflows before business use. No production notarization, external security assessment, other hardware or VoiceOver qualification is claimed here.
